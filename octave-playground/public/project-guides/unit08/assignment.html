For component j: line_cost_j = quantity_j * unit_price_j. For each system: total_cost = sum(all five calculated line costs). The five categories constitute the entire purchase model; no tax, shipping, installation, discount, or additional fee. Sensor data already measure each complete system. Do NOT multiply V*I by panel quantity again.

Write evaluate_system.m to calculate the line costs and total from its quantity and unit-price inputs, then use a meaningful if/elseif/else decision block involving the CALCULATED total and measured performance. Merely entering summed totals, computing unused costs, adding a token unrelated if, or mapping system labels to fixed results does not satisfy this requirement.

Supplied data model, equations, and cleaning

The CSV has NO HEADER and is 125-by-11, with 25 equally spaced observations per day across five days, 09:00–15:00 at 15-minute intervals. Columns: 1 day, 2 time_hr, 3 A voltage_V, 4 A current_A, 5 A temperature_C, 6 B voltage_V, 7 B current_A, 8 B temperature_C, 9 C voltage_V, 10 C current_A, 11 C temperature_C.

Apply ONE shared row mask: reject an entire row when ANY sensor in columns 3–11 is -999, or when ANY voltage/current column (3,4,6,7,9,10) is negative. Zero voltage/current is valid. The remaining supplied readings satisfy quality rules. Apply the same mask to every column and preserve row order; count each rejected row only once. Do not drop rows separately for each system. Preserve the original CSV.

Let N be the retained observation count across all five days together. All required summary metrics use those same N observations. If N=0, stop with a clear message before calculating percentages. For each system:

  • power_W = voltage_V .* current_A at each retained observation;
  • average_power_W = sum(power_W)/N (mean is equivalent);
  • maximum_power_W = max(power_W);
  • maximum_temperature_C = max(retained temperature_C);
  • meeting_count = number of retained power values >= required_power_W;
  • met_pct = 100 * meeting_count/N, on a 0–100 scale;
  • component line costs and total purchase cost as supplied above;
  • cost_per_avg_W = total_cost_USD/average_power_W; if average is zero, use Inf and mark power performance failed.

Numerical requirements: required_power_W=100; minimum_met_pct=80; budget_USD=800. Exactly 100 W counts as meeting; exactly 80% meets performance; exactly $800 is within budget. Compare full precision, round only display to two decimal places; counts are integers.

Required helper contract: [line_cost_USD, total_cost_USD, qualifies, status_code] = evaluate_system(component_quantity, unit_price_USD, met_pct, budget_USD, minimum_met_pct)

Inputs quantity/prices are equal-length real nonempty numeric row vectors, with nonnegative finite values. met_pct is a finite scalar percentage in [0,100], budget nonnegative finite scalar, minimum_met_pct a finite scalar in [0,100]. The helper accepts any matching nonempty component-vector length for independent practice checks. It must use its arguments, not main-workspace variables, system names, or fixed thresholds.

Outputs: line_cost_USD is a row vector of quantity .* unit price; total_cost_USD is their sum (scalar); qualifies is scalar logical; status_code is exactly one of these character vectors:

CodeConditions
'qualifies'met_pct >= minimum_met_pct AND total_cost_USD <= budget_USD
'fails_performance'met_pct < minimum_met_pct AND total_cost_USD <= budget_USD
'over_budget'met_pct >= minimum_met_pct AND total_cost_USD > budget_USD
'fails_both'met_pct < minimum_met_pct AND total_cost_USD > budget_USD

Use meaningful if/elseif/else branching for these four outcomes, with qualifies true only for 'qualifies'. Nested or differently ordered branches are acceptable if all outcomes work. Logical indexing is appropriate elsewhere, but cannot replace this classification block with arithmetic, a lookup table, or hard-coded flags. The helper must return values rather than only printing messages.

Call the same helper for A, B, C. Recommend the system with lowest calculated cost among qualifies=true. If no system qualifies, recommended_index=0 and recommended_system='none'. For equal qualifying costs, choose the first in A/B/C order, purely to make output deterministic. This tie rule adds no modeling. Derive the recommendation from helper outputs, never a typed answer.
